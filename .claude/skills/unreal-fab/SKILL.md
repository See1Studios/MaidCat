# Unreal Fab Plugin Playbook (UE 5.4+)

How the engine-bundled **Fab** plugin (`Engine/Plugins/Fab`) actually moves assets, and where the automation boundary sits. All facts below are verified against the UE 5.5 plugin source and a live import.

---

## The Automation Boundary (read this first)

```
DOWNLOAD + IMPORT   = driven by the web frontend (embedded Chromium UI).  MANUAL ONLY.
POST-IMPORT         = /Game/Fab/<product>/ .uasset files -> free to script with Python.  AUTOMATABLE.
```

- **You cannot script the download/import.** The real entry point `UFabBrowserApi::AddToProject(DownloadUrl, Metadata)` exists, but:
  - It is a plain `UFUNCTION()` with **no `BlueprintCallable`** → not exposed to Python or Blueprint.
  - `DownloadUrl` is a **server-signed URL** generated by the Fab backend when the user clicks an asset in the web UI. It cannot be forged or replayed externally.
- **Do not promise "auto-pull from My Library".** There is no public API, no console command, and no Python hook for it. The user must click **Add to Project** (or drag-drop) in the Fab panel / Epic Launcher.
- **Do** automate everything *after* import: renaming, texture compression fixes, material instancing, foliage/landscape setup, level placement.

## Instructions

### 1. Import Result Layout
- Assets land flat in `/Game/Fab/<ProductName>/`, where `<ProductName>` is the listing title with spaces and special chars replaced by `_`.
  - e.g. `"FREE Desert Terrain / Landscape"` → `Content/Fab/FREE_Desert_Terrain___Landscape_/`
- One folder holds **mesh(es) + material(s) + textures together** (no Meshes/Textures/Materials subfolders).
- **"Terrain" / "Landscape" in a Fab title usually means a static-mesh terrain model + PBR texture set — NOT a UE Landscape-actor layer material.** Always inspect the folder before assuming. Verified example contents:
  - `model.uasset`, `model2.uasset`, `model3.uasset` (LODs/variants), `Material_*.uasset`, `basecolor`, `*_NormalGL`, `*_Roughness`.

### 2. Console Commands (the only scriptable surface)
Callable from the editor console or `unreal.SystemLibrary.execute_console_command(world, "Fab.X")`:

| Command | Effect |
|---|---|
| `Fab.Login` | Trigger interactive login |
| `Fab.Logout` | Clear persistent auth |
| `Fab.ShowSettings` | Open the Fab settings window |
| `Fab.ClearCache` | Wipe the download cache dir |
| `Fab.SetEnvironment <prod\|gamedev\|test>` | Switch backend env (forces re-auth) |

There is **no** `Fab.Download` / `Fab.Import` command. These manage auth/cache/env only.

### 3. Quality & Format Settings (pre-download tuning)
`UFabSettings` (config = `EditorPerProjectUserSettings`) controls what gets downloaded:
- `PreferredQualityTier`: `Low | Medium | High | Raw` (default `Medium`) — for Megascans-style assets.
- `PreferredDefaultFormat`: `GLTF | FBX` (default `GLTF`). Falls back to best available if the preferred format is missing.
- `CacheDirectoryPath`: where downloads are cached (see below).

Set these **before** the user downloads to control output quality/format.

### 4. Locating What Was Downloaded / Imported
- **Imported assets (source of truth)**: enumerate `/Game/Fab/` via the Asset Registry, or check disk at `Content/Fab/`.
- **Listing-ID map (the "alias" the user sees)**: `EditorPerProjectUserSettings.ini` →
  ```ini
  [/Script/Fab.FabLocalAssets]
  PathsListingID=(("/Game/Fab/<product>", "<listing-guid>"), ...)
  ```
  Maintained by `UFabLocalAssets::AddLocalAsset` (path ↔ listing GUID). Use it to know which `/Game` path came from which Fab listing.

## Cache & Tracking (reference paths)

**Conversion boundary**: the cache holds **raw DCC/exchange files** (`.gltf` + `.bin`, `.png`, `.jpg`) — engine cannot use these directly. `.uasset` only ever exists *after* Interchange import into `/Game/Fab/`. So: `cache = source format`, `/Game/Fab = imported uasset`. One `.png` → one `Texture2D.uasset` (same base name, e.g. `basecolor.png` → `basecolor.uasset`); one `.gltf` → `StaticMesh` + `Material` uassets.

```
Download cache (raw source format, temporary, 10-day expiry) — NO .uasset here:
  <CacheDirectoryPath>\<listing-guid>\source_extracted\<name>_extracted\
  default CacheDirectoryPath = %TEMP%\FabLibrary   (FPlatformProcess::UserTempDir()/"FabLibrary")
  contains: model.gltf + .bin (mesh), basecolor.png, *_NormalGL.jpg, *_Roughness.png (images)
            (also the original .zip before extraction)

        │  Interchange import  (only step that produces .uasset)
        ▼
Project import target:
  Content/Fab/<ProductName>/*.uasset   (mesh/material/texture, flat)

Listing-ID tracking:
  Saved/Config/WindowsEditor/EditorPerProjectUserSettings.ini  [/Script/Fab.FabLocalAssets]
```

Source refs: `FabSettings.h:62` (cache default), `FabAssetsCache.cpp:9` (10-day expiry), `FabAssetsCache.h:14` (`GetCacheLocation`), `FabLocalAssets.h:20-25` (path↔ID map), `FabConsoleCommands.cpp` (console cmds), `FabBrowserApi.h:82-83` (`AddToProject`, not BlueprintCallable).

## Gotchas & Pitfalls

### "Imported but not on disk yet"
Right after **Add to Project**, the assets live only in editor memory + the Asset Registry. `Content/Fab/` does **not exist on disk** until the user does **Save All (Ctrl+Shift+S)**. Scripts that scan the filesystem will find nothing while the `.ini` already lists the paths.
- **Fix**: Save first (or use the Asset Registry, not raw disk globbing) before Python post-processing.

### The download cache is temporary
Cached zips/extracted sources under `%TEMP%\FabLibrary` expire after **10 days** and live in the OS temp dir — never treat them as a permanent asset source. Work from `/Game/Fab/` (the imported `.uasset`s), not the cache.

### Title ≠ asset type
A listing named "...Terrain / Landscape" is commonly a **static-mesh model**, not a Landscape-actor material. Inspect the folder contents before building tools around an assumed type.

### No headless / CI import
Because import requires the authenticated web frontend and a signed URL, Fab assets **cannot be pulled in a headless/automation build**. Acquire them once interactively, commit them to the project (or VCS), then automate downstream.

### `UFabBrowserApi` is not your API
It looks like a scripting entry point but is wired only to the internal C++ ↔ web-bridge. Not callable from Python/BP. Don't build on it.
